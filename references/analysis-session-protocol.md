# 数问统一分析会话协议

本文件是各数问分析技能和专家共享的编排约定。它定义每次分析的共同步骤，不替代具体 Skill 的专业方法。引用此协议的分发包必须包含本文件的本地副本。

## 会话流程

1. **理解任务**：复述要回答的问题和对应决策，判断任务类型与交付对象。简单问答不强制展示冗长计划。
2. **澄清关键条件**：只询问会改变结论的缺项（统计对象、周期、指标定义、业务范围等）。可安全默认的条件注明假设后继续；不要反复询问已有材料能回答的问题。
3. **发现可信来源**：列明用户上传文件、已授权连接器或可用文档；区分原始数据、语义/指标定义和二手描述。无权限或无连接器时，不假装能读取。
4. **检查数据充分性**：核对覆盖期、粒度、类型、单位、缺失、重复、关联基数、刷新时间和可比性中与当前任务相关的项目。将零值、缺失值、被过滤值区分开。
5. **预览分析计划**：对非平凡分析，简要列出目标、来源、周期、指标/口径、维度/筛选、方法、预期输出和主要限制。只有改变决策的歧义需要阻断并提问；其余以可见的临时假设继续。
6. **受控执行**：只调用当前会话可见、已授权且适用的工具。数据库默认只读；遵循连接器返回上限、超时和分页。没有执行权限时提供可执行方案，并标注未执行。
7. **核验与解释**：检查控制总额、分母、单位、行数、汇总对账和方法前提。区分：事实（有直接证据）、判断（对事实的解释）、假设（待验证机制）、建议（行动选择）。每个重要发现关联来源/计算和限制；不将相关性说成因果。
8. **连续追问**：后续问题默认沿用已确认来源、口径和计划。若周期、指标、数据或方法改变，指出变更并更新计划版本；不得默默替换口径。
9. **交付与副作用**：报告/图表只基于已核验结果生成。创建或更新用户明确要求的私有草稿后，回读并验证；公开发布、分享、发送、修改源数据或其他外部副作用必须单独确认。Connector 能力缺失时说明边界。

## Analysis Plan 最小清单

- `goal`：业务问题及要支持的决策。
- `task_type`：数据体检、指标诊断、经营复盘、行业研究、报告开发等。
- `sources`：来源、权限范围、权威性/用户提供状态、数据新鲜度或未知状态。
- `time_range`：周期、时区、比较基准和周期完整性。
- `metrics`：实体、定义/公式、单位、粒度、分子分母、过滤/退款/去重规则。
- `dimensions` / `filters`：分析分组和筛选条件。
- `method`：计划采用的方法及适用前提。
- `quality_checks`：影响当前问题的数据质量与覆盖检查。
- `output`：表格、图表、简报、报告或用户要求的其他成果。
- `assumptions` / `limits`：临时假设、数据缺口及不可支持的结论。
- `approval_required`：是否涉及写入、公开发布、分享或外部动作。

计划可以用自然语言展示，不要求在 WorkBuddy 中伪造未实现的结构化状态持久化。若工具或平台不能保存计划，应在同一会话中明确沿用并在计划变更时说明。

## 结果表达

对正式分析任务，优先组织为：

1. **问题与范围**（目标、来源、时间、口径）；
2. **关键发现**（事实与数值先行）；
3. **解释层次**（判断与假设分开）；
4. **下一步**（可验证动作、观察指标与需要的补充数据）；
5. **限制/待确认事项**。

结果中的每个数字要带单位和周期。未读取、未计算、未生成或未验证的内容必须明确写为计划、估算或未执行，不得呈现为已完成结果。
